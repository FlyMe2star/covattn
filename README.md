# covattn

Mechanistic diagnosis and training-free repair of covariate-effect attenuation in Chronos-2.

## Layout

```
src/covattn/   systems.py (synthetic forced systems + exact counterfactuals), model.py (Chronos-2 wrapper),
               hooks.py (hooked re-execution: record / patch / cross gain / REG bias), decompose.py,
               patching.py, repair.py (R1 top-k cross gain, R2 learned gates), baselines.py (ARX, context
               dither reimpl., full fine-tune / LoRA via the official Chronos2Pipeline.fit),
               real_data.py (EPF covariate tasks, univariate datasets), metrics.py, io_utils.py
scripts/       verify_model.py (stage-0 source checks), exp1_phenomenon.py, exp2_mechanism.py,
               exp3_repair.py, exp4_real_and_univariate.py, exp5_ablations.py,
               make_figures.py (figures 1-5, PDF), make_tables.py (tables 1-4, LaTeX booktabs)
docs/          model_notes.md (verified model internals), model_facts.json
colab/         run_all.ipynb (regenerate with `python tools/make_notebook.py`)
tests/         pytest; `-m model` tests need the HF weights
```

## Local (Windows, tested: Win 11, RTX 4060 Laptop 8 GB, Python 3.11)

```powershell
py -m uv pip install --python .venv\Scripts\python.exe torch==2.11.0 --index-url https://download.pytorch.org/whl/cu128
py -m uv pip install --python .venv\Scripts\python.exe -r requirements.txt -e .
.venv\Scripts\python.exe -m pytest -q                 # all tests (downloads amazon/chronos-2 once)
.venv\Scripts\python.exe scripts\verify_model.py
.venv\Scripts\python.exe scripts\exp1_phenomenon.py --quick
.venv\Scripts\python.exe scripts\exp1_phenomenon.py --resume
```

WSL2 also works and is preferable for long runs. On native Windows, check that the driver supports the
CUDA version of the torch wheel (`nvidia-smi` "CUDA Version" >= 12.8 for cu128). DataLoader workers default
to 0 on Windows (`io_utils.default_num_workers`). Close GPU-heavy applications (games, GPU wallpapers)
during runs: the encoder's group attention spans the whole batch, and contention made the laptop GPU drop
off the bus once (driver reset requires a reboot); everything is resumable.

## Colab (A100) - default for anything longer than a few minutes

[Open `colab/run_all.ipynb` in Colab](https://colab.research.google.com/github/FlyMe2star/covattn/blob/main/colab/run_all.ipynb).
Cells: mount Drive → clone / hard-update from GitHub `main` → `pip install -r requirements.txt` → GPU check →
`RESULTS_DIR=/content/drive/MyDrive/pakdd27/results` → smoke test → one cell per experiment, all with `--resume`.

Workflow: edit and test locally → `git push` → in Colab re-run cell 2 (pulls the latest commit) and the
experiment cell. Results go to Drive; each run's `config.json` records the commit hash it ran on.
With Google Drive for desktop the same directory is visible locally, e.g.
`$env:RESULTS_DIR = "H:\我的云端硬盘\pakdd27\results"` (PowerShell) for analysis / `--summary-only`.
Leave `RESULTS_DIR` unset for local `--quick` runs so scratch results stay in `./results`.
The notebook is generated by `python tools/make_notebook.py`; edit that file, not the `.ipynb`.

## Conventions

* Results: `$RESULTS_DIR/<exp>/<run>/` with `config.json` (config + git commit + env), `metrics.jsonl`
  (one line per finished sub-task; `--resume` skips those), `cells/*.npz` (raw per-sample arrays),
  `done.marker`, `log.txt`. Reports: `$RESULTS_DIR/reports/`. `RESULTS_DIR` defaults to `./results`.
* `--resume` refuses a changed config except for keys that only choose which sub-tasks run or how fast
  (`contexts`, `batch_size`, `device`), so a run can be split between machines: copy
  `results/exp1/main` to Drive and continue with `--resume --contexts 2048` on Colab.
* `--amp {off,bf16,fp16}`; default `off` (fp32). `--batch-size` counts series (rows), halves on OOM;
  default 128 (group attention cost grows with rows²).
* Every script prints a time estimate for RTX 4060 and A100 (measured on the current device; the other is
  scaled by a fixed rough factor and labelled as such).

## Experiments

| script | what | where |
|---|---|---|
| `exp1_phenomenon.py` | effect gain g across systems / L / inputs, ARX reference | Colab (done) |
| `exp2_mechanism.py` | decomposition, activation patching, REG sink, cross-gain preview (val split) | Colab, ~45 min L4 |
| `exp3_repair.py` | R1 / R2 / dither / full FT / LoRA / ARX on synthetic test (ID + 3 OOD settings) | Colab |
| `exp4_real_and_univariate.py` | EPF covariate tasks (shuffle / no-cov proxies) and univariate preservation | Colab, after Exp3 |
| `exp5_ablations.py` | which heads / layers, train-only head ranking, random heads, delta, L, noise | Colab, after Exp3 |
| `make_figures.py`, `make_tables.py` | figures and tables from result files only (no model) | anywhere |

Canonical runs used for the paper: `exp1/main`, `exp2/main`, `exp3/v2` (+ LoRA added with
`--add-methods ft_lora`), `exp4/v2lora`, `exp5/main`. `exp3/main` and `exp4/main` are superseded
(full FT ran out of memory; noisy R2 gates) and kept only for the record; `exp4/v2l` ran before LoRA existed.

```bash
python scripts/exp3_repair.py --resume --run-name v2
python scripts/exp3_repair.py --resume --run-name v2 --add-methods ft_lora   # add a method to finished cells
python scripts/exp4_real_and_univariate.py --resume --run-name v2lora --exp3-run v2
python scripts/exp5_ablations.py --resume --exp3-run v2
python scripts/make_figures.py --exp3-run v2 --exp5-run main
python scripts/make_tables.py --exp3-run v2 --exp4-run v2lora --exp5-run main
```

Figures (`reports/figs/`): fig1 g by family and L with ARX (non-periodic inputs vs multisine);
fig2 true vs predicted effect, zero-shot / R1 / R2 (pair with the median zero-shot g of pre-declared cells);
fig3 restoration heatmaps (per-head group-attn cross term; layer-level time-attn / group-attn / MLP);
fig4 REG attention mass vs g and the REG-bias intervention; fig5 R1 k x gamma (val) and head-set ablation.
Tables (`reports/tables/`): table1_synthetic, table2_real_cov, table3_univariate, table4_ablations.

Every script has `--quick` (minutes, CPU is fine) and `--summary-only` (rebuild reports from saved arrays).
Train / val / test are disjoint seed streams (`systems.make_rng`). Exp2 and all selection use val; reports
are generated only from result files.

## Numerical precision note

All forward passes are fp32, except that in `exp3/v2` the test evaluation (all methods, including
zero-shot and the LoRA cells added later) ran in TF32: the official `Chronos2Pipeline.fit` leaves
`torch.backends.cuda.matmul.fp32_precision` at TF32 after fine-tuning (verified locally). Exp5 re-evaluates
the same samples in fp32: element-wise differences up to 9e-3 on effects of size ~4, pooled median g equal
to 3 decimals. `baselines.finetune` now restores IEEE fp32 after `fit`.
